# Dalnovid — план развития

Текущая версия: **0.1.0-alpha.1** (Windows-клиент + сервер, первая сборка).

---

## Версия 0.2.0

### Адресная книга с синхронизацией и сквозным шифрованием

**Цель.** У пользователя есть учётная запись на сервере Dalnovid (общем или своём). После входа его адресная книга одинаково доступна на всех устройствах: компьютере, планшете, телефоне. Книгой можно поделиться с доверенными людьми. Сервер хранит книгу только в зашифрованном виде и не может её прочитать.

#### Что видит пользователь

- **Регистрация и вход** по почте (или логину) и паролю. Без входа приложение работает как сейчас: подключение по ID, история только на этом устройстве.
- При регистрации показываем **ключ восстановления** и просим его сохранить. Без него и без пароля книгу восстановить невозможно — сервер её не расшифрует.
- Раздел **«Адресная книга»** вместо «Устройства»: устройства, группы, теги, заметки, поиск, статус «в сети».
- **Поделиться книгой**: владелец добавляет доверенного пользователя по логину, выбирает роль, сверяет отпечаток его ключа (как код сеанса). Доступ можно отозвать.
- **Офлайн-работа**: копия книги хранится на устройстве (тоже зашифрованная) и синхронизируется при появлении связи.

#### Роли

| Роль | Читать | Изменять записи | Делиться и отзывать доступ | Удалить книгу |
| --- | --- | --- | --- | --- |
| Владелец | да | да | да | да |
| Редактор | да | да | нет | нет |
| Читатель | да | нет | нет | нет |

У пользователя может быть несколько книг: личная (создаётся автоматически) и общие — свои или те, которыми поделились с ним.

#### Шифрование (сквозное, сервер — «слепое хранилище»)

1. При регистрации клиент создаёт пару ключей пользователя (X25519 + Ed25519 для подписи).
2. Закрытый ключ шифруется ключом, выведенным из пароля (Argon2id), и в таком виде хранится на сервере, чтобы войти можно было с нового устройства. Копия закрытого ключа шифруется ключом восстановления.
3. На сервер для входа уходит не пароль, а производное от него значение (отдельная ветка Argon2id). Сервер хранит его хэш, но ключ шифрования из него получить не может.
4. У каждой книги свой случайный ключ (XChaCha20-Poly1305). Записи шифруются этим ключом.
5. Ключ книги «заворачивается» открытым ключом каждого участника (владельца и доверенных) и хранится на сервере отдельно для каждого.
6. **Поделиться** — значит завернуть ключ книги для открытого ключа нового участника. Перед этим клиент показывает отпечаток ключа для сверки, чтобы сервер не подменил ключ.
7. **Отозвать доступ** — значит сменить ключ книги, перешифровать записи и заново завернуть ключ для оставшихся участников.
8. Изменения подписываются ключом автора, чтобы сервер не мог подделать запись.
9. Сервер видит только служебное: кто участник книги, роли, размеры и время изменений. Имена устройств, ID, заметки и сохранённые пароли он не видит.

Смена пароля перешифровывает только закрытый ключ пользователя, книги не трогаются. Если забыт и пароль, и ключ восстановления, данные теряются — об этом честно предупреждаем при регистрации.

#### Синхронизация

- У каждой записи есть версия. Клиент отправляет изменения пачкой и получает чужие изменения с последней известной версии.
- Конфликты решаются по записи: побеждает последняя версия, проигравшая сохраняется в истории на 30 дней.
- Изменения от других участников приходят быстро (long-poll или WebSocket) без ручного обновления.

#### Сервер (`dalnovid-server`)

- Новый сервис API рядом с hbbs (тот же бинарник или отдельный `dalnovid-api`), HTTPS, SQLite по умолчанию и PostgreSQL как вариант.
- Таблицы: пользователи, сеансы и токены, книги, участники книг (роль и завёрнутый ключ), зашифрованные записи, журнал действий.
- Защита: ограничение частоты попыток входа, блокировка после серии неудачных попыток, короткоживущие токены с обновлением, TOTP-2FA (можно в 0.2.x).
- Регистрацию на своём сервере администратор может открыть, закрыть или сделать только по приглашению.
- Журнал действий: вход, выдача и отзыв доступа, удаление — без содержимого записей.
- Резервная копия базы безопасна сама по себе: в ней только зашифрованные данные.

#### Клиент (`dalnovid-client`)

- В клиенте уже есть заготовки адресной книги и входа (`flutter/lib/models/ab_model.dart`, `user_model.dart`, `group_model.dart`, API `/api/ab/*`). Берём их интерфейс за основу, а транспорт и модель данных переводим на зашифрованный формат.
- Криптография — в Rust-ядре (`libsodium`/`RustCrypto`), во Flutter только интерфейс.
- Ключи на устройстве хранятся в системном хранилище: Windows DPAPI, macOS/iOS Keychain, Android Keystore, Linux Secret Service.
- Экраны по макетам редизайна: вход/регистрация, ключ восстановления, адресная книга, диалог «Поделиться» со сверкой отпечатка, участники и роли.

#### Готово, когда

- [ ] Регистрация, вход и выход на всех платформах; ключ восстановления показан и проверен
- [ ] Книга синхронизируется между двумя устройствами одного пользователя
- [ ] Владелец делится книгой, доверенный пользователь её видит; роли соблюдаются
- [ ] Отзыв доступа меняет ключ: отозванный пользователь не читает новые записи
- [ ] В базе сервера нет ни одного открытого имени, ID или заметки (автотест на дамп базы)
- [ ] Офлайн-изменения сливаются без потерь
- [ ] Описание протокола шифрования опубликовано в `docs/` серверного репозитория

## Бэклог (согласовано раньше, версия не назначена)

- Редизайн клиента по утверждённым макетам: светлая и тёмная темы, телефон, планшет, компьютер; знак «Перспектива»
- Файлы иконок со знаком (.ico, .icns, Android/iOS) и замена иконки в сборках
- Ребрендинг, этап 2: имена бинарников, ссылки и тексты в интерфейсе
- Шифрование всегда, включая прямое IP-подключение; закрепление ключа сервера (TOFU); Argon2 для паролей
- Понятная диагностика подключения: какой шаг упал и что делать; запасной путь через 443/WebSocket
- Профили серверов и белый список устройств
- Автообновление с подписанными релизами; подпись сборок
- Веб-панель администратора и журнал аудита
- Ссылка-приглашение для помощи родственникам
- Сборки для macOS, Linux (включая Flathub), Android, iOS
